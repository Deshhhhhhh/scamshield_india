# ADR 0005 — Golden set + CI regression gates, not vibes

**Status:** accepted · 2026-11-16

**Context.** ML demos are usually "works on my 5 examples". Hiring teams (and honest
engineering) need reproducible numbers on unseen data.

**Decision.** An 80-message hand-written golden set (`data/golden/golden_set.csv`), disjoint
from training, spans all 13 scam types + 15 safe messages. `evaluation/evaluate.py` scores
baseline ML / LLM-fallback / combined; CI fails if combined scam-F1 < 0.90 or golden/train
overlap. `docs/results.md` is regenerated by `make evaluate`.

**Trade-offs.**
- ✅ Regression protection on every PR; honest, checkable numbers.
- ✅ Forces documented model versions (`m1-logreg-tfidf-v1`) + eval artifacts in CI.
- ❌ 80 messages can be overfit or unrepresentative — mitigated by disjointness from training,
     documented per-type accuracy, and borderline-language safe examples (negations).
- ❌ Gate ratchets: raising the bar requires adding data, not tweaking prompts.

**Rejected alternatives.** Kaggle-only splits (UCI is 2005-era English, not Indian scams);
LLM-as-judge without ground truth (unverifiable); skipping evaluation until "later" (never ships).

**Revisit when.** A consented real-world labelled sample (1k+) exists → replace golden, keep the gate.
